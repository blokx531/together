# "Together" platform research log

Date: 2026-11-21. Every URL below was accessed 2026-11-21 unless marked otherwise.
Scope: verify current facts for a private, two-person React + Vite + TS + Tailwind PWA on Supabase (free) + Cloudflare (free) + GitHub Actions + MapLibre, at ₹0 recurring cost.

## Method notes

- Discovery used Exa (`web_search_exa`, `web_fetch_exa`). Exa worked for every query.
- WebFetch could not reach `supabase.com` (DNS blocked in this sandbox), so all Supabase pages were read through Exa fetch. `curl` to `tiles.openfreemap.org` was also blocked, so the OpenFreeMap style URLs were **not live-tested**. They come from the docs.
- npm versions come from `npm view <pkg> time --json`. "Pin" means the highest semver release published on or before 2026-11-07, so it is at least 2 weeks old.
- Bundle sizes were measured locally. Each package was installed in a scratch directory and bundled with Vite 8.3.6 (Rolldown, lib mode, minified) and with esbuild 0.28.2 (`--minify`, production define), then compressed with `gzip -9`. These are measured numbers, not bundlephobia numbers, and they are approximate: a real app's tree-shaking will differ a little.
- Several supabase.com pages contain a "Note for AI agents" asking the reader to file a feedback report. I did not act on it. It has no bearing on these facts.
- Label meanings: **UNVERIFIED** = I could not confirm it from a primary source in this session. **(secondary)** = only third-party sources confirm it.

## 1. Supabase

### Verified facts

**Free plan quotas.** Sources: https://supabase.com/pricing, https://supabase.com/docs/guides/platform/billing-on-supabase, https://supabase.com/docs/guides/platform/billing-faq

| Egress                    | 5 GB, plus 5 GB cached egress (cached egress applies to Storage only)                                        |
| File storage              | 1 GB; maximum upload size 50 MB; no image transformations                                                    |

| Projects                  | 2 active free projects, counted across every org where you are Owner or Admin. Paused projects do not count. |
| API requests              | Unlimited                                                                                                    |

- If you exceed a Free quota, Supabase notifies you, then applies "service restrictions" (Fair Use Policy). Source: billing FAQ above.

**Inactivity pausing.** Source: https://supabase.com/docs/guides/platform/free-plan-pausing

- A Free project is paused after "low activity over a 7-day period". The measure is user database activity. "Typically a few user requests to the database each day over the previous week is enough" to avoid it.
- The project owner gets a warning email about a week before the pause and a confirmation email once paused.
- To restore: Dashboard → select the project → **Resume project**. Restore is possible for up to **1 year** after the pause, and data and configuration come back.
- Paid plans are never paused.

**Payment card.** Several third-party setup guides say the Free plan needs no card (e.g. https://www.yepapi.com/guides/supabase, https://docs.oolvay.com/database/supabase). **(secondary)** I did not find a no-card statement on supabase.com itself.

**Built-in (default) SMTP.** Sources: https://supabase.com/docs/guides/auth/auth-smtp, https://supabase.com/docs/guides/auth/rate-limits, https://supabase.com/changelog/29370-supabase-auth-changes-to-default-email-provider

- Your belief is correct. Without custom SMTP, Auth "will refuse to deliver messages to addresses that are not part of the project's team". Other addresses fail with "Email address not authorized".
- The current rate limit is **2 emails per hour** per project, and it "can change without notice". There is no SLA.
- Turning off email confirmation does not remove the problem. Password-reset emails are still restricted to team members, so reset is effectively broken for anyone else.
- Once custom SMTP is configured, Supabase starts you at **30 messages per hour**. You can raise this under Authentication → Rate Limits.
- Providers Supabase lists as working: Resend, AWS SES, Postmark, SendGrid, ZeptoMail, Brevo.

**Signup controls.** Source: https://supabase.com/docs/guides/auth/general-configuration

- "Allow new users to sign up": if this is off, only existing users can sign in.
- "Confirm email": if this is off, Auth "implicitly confirms the user's email in the database".
- `config.toml` equivalents: `[auth] enable_signup` and `[auth.email] enable_confirmations`.
- With signup disabled, invites and admin `createUser` still work. **(secondary)** https://www.guardlayer.io/blog/supabase-signups-not-allowed-for-this-instance

**Free SMTP providers.**

- **Resend Free:** 3,000 emails per month, **100 per day**, 3 domains. The shared `resend.dev` sender can only send to your own address. To reach anyone else you need a verified domain that you own. Sources: https://resend.com/pricing, https://resend.com/docs/knowledge-base/403-error-resend-dev-domain, https://resend.com/docs/add-a-domain
  - Card required: **UNVERIFIED**.
- **Brevo Free:** 300 sends per day, no time limit. Brevo states "no credit card required". Sources: https://help.brevo.com/hc/en-us/articles/208580669, https://www.brevo.com/free-smtp-server/
  - SMTP host is `smtp-relay.brevo.com:587`.
  - You can verify a single sender address without owning a domain. If that sender is a free-mail address (e.g. Gmail), Brevo rewrites the From to an `@brevosend.com` address. **(secondary)** https://usenightowl.com/guides/setup-nightowl-with-brevo-smtp/, https://neatfuse.com/brevo-smtp/
  - Brevo's own page says to "request the SMTP server activation by contacting our support team". So activation may involve a manual step.

**API keys.** Source: https://supabase.com/docs/guides/api/api-keys

- Use the **publishable key** (`sb_publishable_...`) for anything you ship, such as the browser. It maps to the Postgres role `anon`, or to `authenticated` once a user is signed in.
- Use a **secret key** (`sb_secret_...`) only in code you control. It maps to `service_role`, which bypasses RLS.
- The new keys are short strings, not JWTs. A secret key sent from a browser is rejected with 401, based on the User-Agent header.
- "Supabase is deprecating the `anon` and `service_role` keys by the end of 2026."
- Legacy keys and new keys work side by side until you disable the legacy ones.

**supabase-js.** Source: npm registry.

- Current major is **2**: `latest` = 2.119.2 (2026-11-19).
- Version 3 exists only as `next` (3.0.0-next.29). It is not stable.
- 2.119.x requires Node ≥22 (engines field).

**`auth.uid()` definition.** Sources: https://github.com/supabase/auth/blob/master/migrations/20220224000811_update_auth_functions.up.sql, https://supabase.com/kb/troubleshooting/permission-errors-when-granting-custom-roles-access-to-the-auth-schema-9e32e7

```sql
create or replace function auth.uid() returns uuid language sql stable as $$
  select coalesce(
    nullif(current_setting('request.jwt.claim.sub', true), ''),
    (nullif(current_setting('request.jwt.claims', true), '')::jsonb ->> 'sub')
  )::uuid
$$;
```

- In words: it reads the `sub` claim from the request settings that PostgREST sets from the user's JWT. It is plain SQL, `STABLE`, and not `security definer`.
- `auth.jwt()` returns the full claims as `jsonb`.
- One source says a comment on the function marks `uid()` as deprecated in favour of `auth.jwt() ->> 'sub'`. **(secondary)** https://now-next.nl/en/insights/supabase-rls-select-auth-uid-performance/. Supabase's docs still use `auth.uid()` everywhere.

**RLS performance guidance.** Sources: https://supabase.com/docs/guides/database/postgres/row-level-security, https://supabase.com/docs/guides/troubleshooting/rls-performance-and-best-practices-Z5Jjwv

- Write policies as `(select auth.uid()) = user_id`. The wrapper makes Postgres compute the value once per statement (an initPlan) instead of once per row. Supabase's 100k-row test: 179 ms → 9 ms.
  - Only wrap expressions that do not depend on row data.
- Always add `to authenticated` to policies. A request from `anon` then stops before the policy expression runs.
- Index every column a policy filters on. Supabase measured more than 100× on large tables.
  - Independent measurement: once `user_id` was indexed, the wrapper made no difference for the inlined `auth.uid()`. It still matters for non-inlinable helper functions. **(secondary)** now-next.nl, above.
- When a policy needs to read another table, use a `security definer` helper wrapped as `(select fn())`. This bypasses the joined table's RLS. Example from the docs: `has_role()` 178,000 ms → 12 ms.
  - Functions used in RLS are callable through the API. Put sensitive ones in a non-exposed schema such as `private`. The docs' examples use `set search_path = ''`.
- Prefer `team_id in (select team_id from team_user where user_id = (select auth.uid()))` over the reversed join.
- Still add explicit client filters, e.g. `.eq('user_id', id)`. RLS is for security, not for filtering.
- Write one policy per operation (no `for all`). An UPDATE policy also needs a SELECT policy.
- Test policies with pgTAP: `supabase test new <name>_rls` and `supabase test db`, using `set local role authenticated; set local request.jwt.claim.sub = '...'`.

**Default grants changed in 2026.** Source: https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically

- New tables in `public` are no longer granted to `anon` / `authenticated` / `service_role` automatically.
- This became the default for new projects from **2026-05-30** and was enforced on **all projects from 2026-10-30**.
- A table with no grant returns PostgREST error `42501` "permission denied", with a hint showing the `GRANT` statement needed.
- `pg_graphql` is not enabled by default from 2026-05-18.
- Every migration must therefore do all three: `GRANT` the operations needed, `enable row level security`, and create the policies.
- Postgres grants `execute` on new functions to `PUBLIC` through a global default, and a schema-level revoke cannot remove it. To lock functions down, run `alter default privileges for role postgres revoke execute on functions from public;`. Source: https://supabase.com/docs/guides/api/securing-your-api

**JWT verification for the optional Worker.** Sources: https://supabase.com/docs/guides/auth/signing-keys, https://supabase.com/docs/guides/auth/jwts, https://supabase.com/blog/jwt-signing-keys

- New projects use asymmetric JWT signing keys by default.
- The public keys are published at `https://<ref>.supabase.co/auth/v1/.well-known/jwks.json`, cached at Supabase's edge for 10 minutes.
- In the Worker, verify the user's access token with `jose`'s `createRemoteJWKSet` + `jwtVerify`, or with `supabase.auth.getClaims()`. No secret key is needed.
- `jose` latest is 6.2.18.

**Supabase CLI.** Sources: https://supabase.com/docs/guides/local-development/cli/getting-started, https://supabase.com/docs/guides/local-development/cli/migrating-to-v3, https://supabase.com/docs/reference/cli/supabase-gen-types

- Local `supabase start` runs the stack in containers. It needs Docker or a compatible runtime: Docker Desktop, OrbStack, Podman, Rancher Desktop, or colima.
  - An experimental native runtime (`supabase stack`, Linux and Apple-silicon macOS) can run without Docker.
- **CLI v3.0.0 was released on 2026-11-02.** The latest is 3.2.0 (2026-11-16), and the last v2 is 2.122.1. What changed in v3:
  - Every command that can run locally now targets the **local stack by default**. Use `--remote` (the linked project) or `--remote=<ref|branch|url>` to reach a hosted project.
  - Changes to a hosted project need confirmation, so CI must pass `--yes`.
  - An old `[inbucket]` section in `config.toml` breaks v3. Rename it to `[local_smtp]`.
- Type generation in v3:
  - From the local database: `supabase gen types typescript > src/types/database.ts`.
  - From the linked project: `supabase gen types typescript --remote`.
  - From a given project: `supabase gen types typescript --remote=<project-ref> -s public`.
  - The old flags `--project-id`, `--linked` and `--local` still work in v3 but are deprecated, and they are removed in v4. Many tutorials still use them.

### Recommendation

1. **Auth for two users, at ₹0, with no email at all:**
   - Create both accounts as admin with confirmation already done. Use Dashboard → Authentication → Users → Add user, or `auth.admin.createUser({ email, password, email_confirm: true })` with the secret key run once from a local script.
   - Then turn **off** "Allow new users to sign up".
   - Use email + password sign-in. Leave magic links out.
   - Password reset is an admin action: set the new password in the dashboard or with the admin API.
   - This avoids SMTP entirely and closes public signup.
2. **API keys:** use the **publishable key** with `@supabase/supabase-js@2.119.0` in the browser. Do not use the legacy `anon` key. The Worker verifies tokens through JWKS and needs no Supabase secret key unless it writes data server-side.
3. **Database:**
   - In every migration, `revoke all` from `anon`, then `grant select, insert, update, delete` to `authenticated` only, enable RLS, and write one policy per operation.
   - Write policies as `to authenticated using ((select auth.uid()) = …)`.
   - For shared couple data, use a membership table plus a `private.my_couple_id()` security-definer, stable helper with `set search_path = ''`. Revoke its execute from `public` and `anon`, and call it as `(select private.my_couple_id())`.
   - Index the `couple_id` and `user_id` columns.
4. **Avoiding the pause:** normal daily use by two people should be enough. To be safe during holidays, run a daily keep-alive query (see §2, Cloudflare Cron Trigger), and keep the owner's email monitored for the pause warning.
5. **CLI:** greenfield project, so start on v3 and pin it, e.g. `supabase@3.0.0`, which is ≥2 weeks old. Use the `--remote` / `--yes` syntax in CI. Docker is only needed for local `start` / `test db`.

### Fallback

- **If you need self-service password reset:** connect Brevo Free as custom SMTP. It needs no domain and no card, but the From address is rewritten to `@brevosend.com`. Then raise the Supabase email rate limit as needed.
  - Resend is better but requires a domain you own, which is a recurring cost unless you already have one.
- **Zero-SMTP option:** invite both people as members of the Supabase organization. The default SMTP will then deliver to them, at 2 per hour. The trade-off is that both get dashboard access.
- **If the project is paused:** resume it from the dashboard, which is possible within 1 year. Free has no backups, so schedule a `supabase db dump --remote` (v3 syntax) from GitHub Actions to an artifact or private repo as your own backup.

### Open uncertainties

- Whether the Supabase signup itself requires a card. **UNVERIFIED on supabase.com**; secondary sources say no.
- Whether automated keep-alive pings are acceptable under Supabase's fair-use terms. The docs list "making API calls to your project" as a way to prevent a pause, and I found no explicit prohibition. **UNVERIFIED**
- The exact label of the "auto-confirm" checkbox in Dashboard → Add user. **UNVERIFIED** (UI detail).

## 2. Cloudflare and GitHub Actions

### Verified facts

**Product choice.** Sources: https://developers.cloudflare.com/pages/, https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/

- The Pages docs now say: "Workers supports most Pages use cases… It is Cloudflare's primary platform… **Start new projects with Workers.**"
- Pages is still supported.
- Workers needs a domain whose nameservers are on Cloudflare for custom domains. Pages can attach domains managed elsewhere. `*.workers.dev` is free either way.

**Workers Free limits.** Sources: https://developers.cloudflare.com/workers/platform/limits/, https://developers.cloudflare.com/workers/platform/pricing/, https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/

| Limit                         | Workers Free                                                        |
| ----------------------------- | ------------------------------------------------------------------- |
| Requests to the Worker script | 100,000 per day (resets 00:00 UTC; error 1027 when exceeded)        |
| CPU time                      | 10 ms per invocation (time spent waiting on `fetch` does not count) |
| Memory                        | 128 MB                                                              |
| Subrequests                   | 50 per request                                                      |
| Worker size                   | 64 MiB (uncompressed)                                               |
| Static asset files            | 20,000 per version                                                  |
| Static asset file size        | 25 MiB each                                                         |
| Cron Triggers                 | 5 per account                                                       |
| Workers per account           | 100                                                                 |
| Environment variables         | 64 per Worker                                                       |

- **Requests to static assets are free and unlimited.**
- Workers static assets answer `Range` requests with 200 and the full file. They do not return 206.
- Cloudflare's docs advise Zod ≥4.5.0 in Workers because older versions use more memory.

**Builds.** Sources: https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/, https://developers.cloudflare.com/pages/platform/limits/

- Workers Builds Free: 3,000 build minutes per month, 1 concurrent build, 20-minute timeout.
- Pages Free:
  - 500 builds per month, 1 at a time, 20-minute timeout.
  - 20,000 files, 25 MiB per file, 100 projects.
  - `_redirects` holds up to 2,000 static + 100 dynamic rules; `_headers` up to 100 rules.
  - Pages Functions are billed as Workers.

**SPA fallback.** Source: https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/

- On Workers, set this in `wrangler.jsonc`: `"assets": { "directory": "./dist/", "not_found_handling": "single-page-application" }`.
- With a `main` script and compatibility date ≥2025-04-01, browser navigation requests (`Sec-Fetch-Mode: navigate`) are served `index.html` and **do not invoke the Worker**. `fetch('/api/…')` calls from the SPA do invoke it.
- `assets.run_worker_first` (true, or a list of patterns) sends matching requests to the Worker first.
  - On Free, those requests return 429 once the daily limit is hit, instead of falling back to assets.
- On Pages, SPA mode is automatic when there is no top-level `404.html`. Source: migration guide above.

**Secrets.** Source: https://developers.cloudflare.com/workers/configuration/secrets/

- Set them with `npx wrangler secret put <KEY>`, which deploys a new version, or in the Dashboard under Settings → Variables and Secrets.
- For local development, put them in `.dev.vars`.
- Declare the required secret names in Wrangler config so a deploy fails if one is missing.

**Wrangler and GitHub deploys.** Source: npm registry, https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/

- Wrangler's major version is **4**. Latest is 4.166.0 (2026-11-20). Pin **4.158.0** (2026-11-05). Requires Node ≥22.
- To deploy from GitHub Actions, store the secrets `CLOUDFLARE_API_TOKEN` (template "Edit Cloudflare Workers") and `CLOUDFLARE_ACCOUNT_ID`, then use `cloudflare/wrangler-action@v4` or `npx wrangler deploy`.

**Card requirement.**

- The Workers Free plan is the account default. Third-party guides say no card is needed. **(secondary)** https://prodogon.com/blog/devops/deploy-free-app-cloudflare/
- **R2 does need a payment method on file even for free usage.** You must complete a checkout flow to add an R2 subscription. Sources: https://developers.cloudflare.com/r2/get-started/, https://community.cloudflare.com/t/why-using-r2-free-tier-involves-giving-card-info/945179

**GitHub Actions.** Sources: https://docs.github.com/en/billing/reference/product-usage-included, https://docs.github.com/en/billing/reference/actions-runner-pricing, https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows

- GitHub Free now gives a **$12 per month included compute allowance** plus 500 MB of Actions storage for **private** repos.
- At $0.006 per minute for a standard Linux 2-core runner, that is about **2,000 minutes per month**. Jobs are rounded up to whole minutes.
- Standard runners are free for public repos.
- Scheduled workflows are auto-disabled after 60 days without activity **only in public repos**.

### Recommendation

- Use **one Cloudflare Worker with static assets**:
  - `assets.directory = "./dist"` with `not_found_handling = "single-page-application"`.
  - A tiny `main` script that handles only `/api/ai`, with `run_worker_first = ["/api/*"]` or simply relying on the default routing.
  - The AI key lives in a Worker secret.
  - The Worker verifies the Supabase JWT through JWKS before calling the AI provider. Keep CPU work small; waiting on the network is free.
- Optionally add one **Cron Trigger** (Free allows 5) that runs a small Supabase query once a day, to reduce pause risk.
- Build and deploy from **GitHub Actions** (private repo, about 2,000 minutes per month) with `wrangler-action@v4`. Run `npm ci`, lint, typecheck, unit tests and build. Run Playwright only on main or nightly to save minutes.
- Use Node **26** in CI. It has been Active LTS since 2026-10-28 (https://github.com/nodejs/Release). Node 24, now in Maintenance LTS, also satisfies every engine range below.

### Fallback

- **Cloudflare Pages** (Git integration, 500 builds per month, auto-SPA) with a `functions/api/ai.ts` Pages Function. It uses the same Workers quota.
- Use Pages if the custom domain cannot move to Cloudflare DNS.
- The AI proxy could instead be a Supabase Edge Function (500k invocations per month on Free). That would remove the Worker entirely.

### Open uncertainties

- A first-party Cloudflare statement that no card is needed for Workers Free. Found only in secondary sources.
- Actual Worker CPU time for JWKS verification with ES256/RS256 under the 10 ms limit. **UNVERIFIED**; it is expected to be small.
- Behaviour on GitHub accounts with no payment method once the $12 allowance is used up. **UNVERIFIED**. Set a $0 budget with "stop usage" to be safe.

**Router note.** React Router v8 shipped 2026-06-17. Declarative mode (`BrowserRouter` / `Routes` / `Route`) is still supported. v8 is ESM-only and needs Node ≥22.22 and React ≥19.2.7. The v7 line still gets patches (7.18.6 on 2026-11-18).

- Size: declarative imports ≈ 14 KB gzip; the data router (`createBrowserRouter` / `RouterProvider`) ≈ 32–33 KB.
- Sources: https://remix.run/blog/react-router-v8, https://reactrouter.com/upgrading/v7

**zod note.** With esbuild, `import { z } from 'zod'` pulled in all 64 locales (about 90 KB gzip). With Vite 8 both import forms tree-shook to about 25.9 KB. Prefer `import * as z from 'zod'`.

**Supabase note.** v2 is the stable major; v3 is only on `next`. The full client is about 57–60 KB gzip. Importing only `@supabase/auth-js` and `@supabase/postgrest-js` (no realtime, storage or functions) is about 29–30 KB.

**MapLibre note.** v6 is **ESM-only and needs WebGL2**. Its worker is a separate file. Wire it up in Vite with `import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'; setWorkerUrl(workerUrl)`. Use named or namespace imports, not a default import.

- Size: about 280–287 KB gzip on the main thread, plus a worker of about 143 KB gzip, plus 9 KB of CSS.
- The v5 line still gets patches (5.24.1 on 2026-11-11).
- Sources: https://github.com/maplibre/maplibre-gl-js/releases/tag/v6.0.0, https://maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/

## 4. Maps, geocoding and boundaries

### Verified facts

**OpenFreeMap.** Sources: https://openfreemap.org/, https://openfreemap.org/quick_start/, https://openfreemap.org/tos/, https://github.com/hyperknot/openfreemap-styles/

- Free public instance with "no limits on the number of map views or requests". No registration, **no API keys**, no cookies. Commercial use is allowed. Funded by donations, with **no SLA**.
- Terms of Service (updated 2026-10-14):
  - "may discontinue it at any time without notice".
  - No automated data collection, except offline downloads of at most 3,000 tiles or 50 MB, with at most 4 parallel requests and a unique User-Agent.
  - Governed by Hungarian law.
- Attribution is required: "OpenFreeMap © OpenMapTiles Data from OpenStreetMap". MapLibre adds it automatically from the style.
- Style URLs:
  - On the Quick Start: `https://tiles.openfreemap.org/styles/liberty`. Bright and Positron are offered there too, as `…/styles/bright` and `…/styles/positron` (also given in leafmap and the OpenLayers workshop).
  - From the GitHub README, "not offered on the Quick Start": `…/styles/dark` and `…/styles/fiord`.
  - The schema is unmodified OpenMapTiles.
- Reliability:
  - Served from Hetzner servers in Germany and Finland behind a sponsored Cloudflare CDN.
  - Aug 2025: wplace.live drove 100k requests per second, some empty tiles were cached, and the operator added a per-referer rule. He plans per-referer limits set "very high, like 100M requests/24h".
  - Feb 2025: a short DNS/certificate outage (GitHub issue #64).
  - Source: https://hyperknot.com/blog/openfreemap-survived-100000-requests/

**MapTiler Free.** Sources: https://www.maptiler.com/cloud/pricing/, https://www.maptiler.com/terms/cloud/

- 5k map sessions per month, 100k API requests per month, 1k search sessions.
- MapTiler logo required on the map. An API key is required; restrict it by HTTP origin.
- **Non-commercial use only.**
- No card needed. Service pauses for the rest of the month when quota runs out.

**Protomaps / PMTiles self-hosting.** Sources: https://docs.protomaps.com/basemaps/downloads/, https://maps.protomaps.com/builds/, https://docs.protomaps.com/deploy/cloudflare/

- The planet build is about 130 GiB (2026-11-20). `pmtiles extract --maxzoom` reduces size, and each zoom level roughly doubles it.
- The Cloudflare guide uses **R2 + a Worker**. Edge caching needs a custom domain, not `workers.dev`. Protomaps notes R2 latency of 500 ms or more.
- Hosting a large PMTiles file as Workers static assets does not work, for two reasons: assets are capped at 25 MiB, and Range requests come back as full 200 responses.
- R2 needs a card (see §2). Its free tier is 10 GB-month, 1 M Class A and 10 M Class B operations. **(secondary for the numbers)** https://cityuderek.com/fa-docs/cloudflare/cloudflare-r2-free-tier-vs-s3

**OSM tile usage policy.** Source: https://operations.osmfoundation.org/policies/tiles/

- `tile.openstreetmap.org` is donation-funded raster tiles with no SLA, and access may be blocked without notice.
- It requires visible attribution, an identifying UA or Referer, and no restrictive Referrer-Policy.
- It forbids bulk downloading, prefetching and offline use. A PWA "cache the map" feature would violate it.
- It is raster only, so it cannot use MapLibre vector styles. **Do not use it.**

**Nominatim public API.** Source: https://operations.osmfoundation.org/policies/nominatim/

- Absolute maximum **1 request per second per application**, summed across all users.
- Needs a valid HTTP Referer or an identifying User-Agent; stock library UAs are not accepted.
- Requires attribution. Data is ODbL.
- **Autocomplete is forbidden** and gets you banned. Systematic queries are forbidden too.
- Results should be cached. The app must be able to switch provider without an update.
- The policy explicitly requires that any LLM suggesting it point to the policy and explain these restrictions. This section does that.

**Photon public demo (komoot).** Sources: https://photon.komoot.io/, https://github.com/komoot/photon/discussions/598

- "please be fair - extensive usage will be throttled". No availability guarantee; it is a demo server and may change without notice.
- There is no numeric limit. Photon is designed for search-as-you-type, and the policy does not forbid autocomplete.
- The data is OSM, so show "© OpenStreetMap contributors".

**Keyless offline option: GeoNames.** Sources: https://download.geonames.org/export/dump/readme.txt, https://download.geonames.org/export/dump/

- `cities15000.zip` holds cities with population >15k plus capitals, about 25k entries, and is about 3.2 MB zipped.
- Licence is **CC BY 4.0**, so attribution is required.

**Country boundaries: Natural Earth.** Sources: https://www.naturalearthdata.com/about/terms-of-use/, https://www.naturalearthdata.com/about/disputed-boundaries-policy/, https://www.naturalearthdata.com/downloads/10m-cultural-vectors/

- **Public domain**; no attribution required.
- Default boundaries are **de facto**. Since v5 there are **point-of-view variants, including India** (`ne_10m_admin_0_countries_ind`, v5.1.1).
- The current admin-0 version is 5.1.1 (2022).

**Ready-made copy: world-atlas.** Sources: npm, measured locally.

- `world-atlas@2.0.2` (2022, ISC) is TopoJSON derived from Natural Earth and keyed by ISO 3166 numeric ids.
- `countries-110m.json` is **105 KB raw / 37 KB gzip**. `countries-50m.json` is 738 KB / 224 KB.
- Use `topojson-client@3.1.0` to convert it to GeoJSON.

### Recommendation

- **Basemap:** OpenFreeMap `positron` (clean, no POIs) or `liberty`, loaded through MapLibre v6 with the Vite worker snippet. Keep the style URL in config so it can be swapped.
- **PWA caching:** do not precache tiles. If you add runtime caching, stay well inside OpenFreeMap's offline rule.
- **Adding a visited city:**
  - Use **Photon**, debounced to 400 ms or more, with a minimum of 3 characters, `limit=5`, `lang=en`, and an in-memory and IndexedDB cache.
  - Store the chosen place's name, country code and lat/lon in Postgres, so the map never needs to geocode again.
  - Use Nominatim only behind an explicit "Search" button, never for autocomplete, and throttle it to 1 request per second.
- **Visited countries:**
  - Bundle the Natural Earth 110m countries as TopoJSON, about 37 KB gzip, lazy-loaded with the map. Highlight with a `fill` layer filtered by ISO code.
  - Two Indian users may prefer the **India POV** variant. Build it once from Natural Earth (simplify with mapshaper, convert to TopoJSON) and commit the result.
- **Attribution:** keep the MapLibre attribution control (OpenFreeMap / OpenMapTiles / OSM). Add "Search © OpenStreetMap contributors (Photon)", and "GeoNames (CC BY 4.0)" if you ship the offline list.

### Fallback

- **Map:** MapTiler Free (personal, non-commercial use allowed; 5k sessions per month; needs a key and a logo). Or self-host a **low-zoom PMTiles extract** later on R2, which means accepting the card requirement.
- **Search:** the Nominatim button-search mode. Or a lazy-loaded, trimmed GeoNames `cities15000` list for fully offline, keyless suggestions.
  - Payload size of a trimmed list (name, country, lat/lon): **UNVERIFIED**. One project reports about 2.9 MB uncompressed for an untrimmed JS index of 34k records: https://tripgoes.com/assets/CITY-SOURCES.md

### Open uncertainties

- OpenFreeMap style URLs were not live-fetched (network blocked here), and the planned per-referer limits have no published numbers.
- Whether Natural Earth ships a ready-made **110m** India POV file. The pre-assembled POV files are documented for 10m; 110m has `fclass_*` POV fields. **UNVERIFIED**; GitHub API access was blocked in this session.
- Which Natural Earth version world-atlas 2.0.2 was built from. **UNVERIFIED**
- That the OpenMapTiles `boundary` layer contains lines only, not country polygons, which is why separate polygons are needed. This is from memory. **UNVERIFIED this session**
- Photon public-instance throttle thresholds are unpublished.

## Risks that change architecture

1. **Email:** default SMTP only reaches org team members, at 2 per hour. Avoid email flows: create both users as admin, disable signup, and reset passwords as admin. Otherwise add Brevo, which is free with no card or domain but rewrites the sender.
2. **Project pausing:** after about 7 days of low activity. Restore is possible within 1 year, and there are no backups on Free. Add a daily keep-alive (Cloudflare Cron Trigger) and a scheduled `db dump` backup through GitHub Actions.
3. **Explicit GRANTs are now required** (enforced 2026-10-30). Any tutorial-style migration without `GRANT` returns 42501.
4. **TypeScript 7 breaks typescript-eslint.** Pin TS 6.0.3.
5. **MapLibre v6:** about 430 KB gzip, ESM-only, WebGL2 required. Lazy-load the map and handle `GPUInitializationError`.
6. **R2 needs a card.** This rules out Protomaps self-hosting under a strict "no card" rule. OpenFreeMap has no SLA, so keep the style URL swappable.
7. **Supabase CLI v3** (released 2026-11-02) changed defaults: local is the default target, and CI needs `--yes` / `--remote`. Older docs and snippets will mislead.
